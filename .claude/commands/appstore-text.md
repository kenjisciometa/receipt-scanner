# App Store Connect 公開テキスト作成

対象アプリの**実際のコミット履歴**から、App Store Connect に貼り付けられる
Promotional Text と What's New in This Version を作成してください。

## 入力

ユーザーから以下が提供される（または対話で確定する）:
- 対象アプリのディレクトリ（例: `order_sys/pos/flutter_app`）
- 省略時は、直前の会話で扱っていたアプリ、または現在のディレクトリ

引数例: `/appstore-text order_sys/pos/flutter_app`

## 前提の確認

**推測で書かない。** 必ず以下を実コードから確認する。

1. **バージョンと対象アプリ**
   - `pubspec.yaml` の `version:` を読む（例: `1.1.15+160`）
   - `ios/Runner/Info.plist` の `CFBundleDisplayName` で表示名を確認する

2. **前回リリースの範囲**
   - 可能なら前回提出時のタグ／コミットを特定し、そこからの差分を対象にする
   - 特定できない場合は、ユーザーに「前回提出のバージョンまたは日付」を確認する
   - どちらも不明なら直近コミットを対象とし、**その前提を明示して**提示する

3. **変更履歴の抽出**
   - `git log --oneline -200 -- <app-dir>` で、そのアプリに触れたコミットだけを拾う
   - モノレポなので、**パス指定を省略すると他アプリの変更が混入する**

4. **対応ロケール**
   - `lib/l10n/*.arb` を確認し、ローカライズが必要な言語を把握する

## 手順

### 1. コミットの分類

抽出したコミットを**ユーザーに見える変更**と**見えない変更**に分ける。

| 含める | 除外する |
|--------|----------|
| `feat:` ユーザーが操作・目視できる機能 | `refactor:` 内部構造のみ |
| `fix:` ユーザーが遭遇する不具合 | `test:` テスト追加・修正 |
| 法令対応（レシート表記、TSE、Kassaregister 等） | `docs:` ドキュメント |
| 対応国・言語の追加 | `chore:` ビルド設定（※リリースレーン追加は含めてよい） |
| パフォーマンス改善（体感できるもの） | 未配線のコミット（`unwired` と明記されたもの） |

「unwired」「pin the ... before」等は**まだ動かない or 検証用**なので除外する。

### 2. 出荷実態の検証

**コードが完成していても、出荷・届出が済んでいないものは書かない。**

- 法令対応機能（DE の TSE、SE の Kassaregister 等）は、
  実際にストアで配信され稼働しているかを確認する
- 届出・受理が未完了の機能を「新機能」として書くと、
  審査・顧客の双方に対して到達できない機能を謳うことになる
- 判断が付かない場合は該当セクションを**落とす**か、ユーザーに確認する

### 3. Promotional Text の作成

- **170 文字以内**（厳守。文字数を数えて併記する）
- ビルド再提出なしで差し替え可能なので、**今回の目玉**を置く
- 3 案出し、1 案を推奨として明示する
  - A: 機能前面（今回の目玉機能）
  - B: 訴求軸（対応国、業態、導入メリット）
  - C: 短く刺す版
- 誇大表現を避ける。実稼働していない数値・規模を書かない

### 4. What's New in This Version の作成

- **4000 文字以内**
- 機能領域ごとに見出しを付けて箇条書きにする
  （例: ギフトカード / レシート / レポート / 各国対応 / その他）
- 1 項目 1 行。**ユーザーの言葉**で書く
  - ✗ 「`order_totals` トリガーのオプション別 VAT を修正」
  - ○ 「オプション付き商品の税額が正しく計算されるようになりました」
- 内部用語（テーブル名、プロバイダ名、関数名、コミットハッシュ）を出さない
- 「不具合を修正しました」だけで終わらせない。**何が直ったか**を書く
- 件数が多い場合は、細かい修正を末尾の「その他」に 1〜2 行でまとめる

### 5. ローカライズの確認

- `lib/l10n` に複数ロケールがある場合、ストアの掲載ページも
  多言語化されているかをユーザーに確認する
- 主要市場（fi / sv / ja / de / et など）の掲載ページがあるなら、
  **英語のまま貼ると未完成に見える**ことを指摘し、翻訳の要否を確認する
- 翻訳を作る場合は、各言語で文字数制限を再チェックする

### 6. 提示

1. 確認した前提（対象アプリ、バージョン、差分範囲）を冒頭に書く
2. Promotional Text（3 案、文字数付き）
3. What's New（貼り付け用のコードブロック）
4. **貼り付け前の注意**を明記する
   - ローカライズの要否
   - 出荷実態が不確かで落とした項目、または確認が必要な項目

## 注意事項

- **コミットログを翻訳するだけにしない**: 顧客にとっての価値に変換する
- **出荷していないものを書かない**: コード完成 ≠ 配信済み
- **モノレポのパス指定を忘れない**: 他アプリの変更が混入する
- **文字数を必ず数える**: 超過したテキストは貼り付け時に弾かれる
- **審査リスクを避ける**: 未実装機能、根拠のない優位性、他社比較を書かない
- **不明点は確認する**: 特に前回提出バージョンと法令機能の出荷状況
