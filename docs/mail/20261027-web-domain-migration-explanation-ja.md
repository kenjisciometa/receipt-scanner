# お客様向け説明文 — ドメイン契約を維持したままのWeb移行

**用途:** Web制作の検討中のお客様へ、今後の進め方の説明（契約前）
**日付:** 2026-10-27
**ステータス:** ドラフト（[ ]部分を案件情報で差し替え）
**前提:** 現行サービスでドメインを長期契約済み。契約は維持し、サイト本体のみ弊社制作

---

## 送付文（このまま使える本文）

お世話になっております。

Webサイト制作のご検討、ありがとうございます。現在ご利用中のサービスでドメインを長期契約されているとのことでしたので、その契約を活かしたまま進められる方法をご説明いたします。

### ご安心いただきたい点

まず結論として、**今の契約を解約したり、満了を待つ必要はありません。** そのまま新しいサイトへ移行できます。

少し専門的になりますが、ドメイン関連のサービスは次の3つの層に分かれています。

| 層 | 役割 | 今回の扱い |
|---|---|---|
| ドメインの契約 | ドメイン名を保有する権利 | **現行のまま継続** |
| ドメインの接続先設定（DNS） | ドメインをどのサーバーに向けるか | ここだけ変更 |
| サイト本体 | 実際に表示されるWebサイト | 弊社が新規制作 |

長期契約で縛られているのは一番上の「ドメインの契約」だけです。**その下の「接続先設定」は契約期間中でも自由に変更できます。** ここを弊社のサーバーに向け替えるだけで、ドメイン（例：[ドメイン名]）はそのままに、サイトの中身だけが新しいものに切り替わります。

お客様にとっては、**同じアドレスのまま、ある日サイトが新しくなる**という形になります。

### 今後の進め方

#### ステップ1 — プロトタイプのご確認（現在）

まずは新しいサイトのプロトタイプを制作し、ご覧いただきます。この段階ではお客様の現在のサイトやドメインには一切触れません。弊社の確認用アドレスでお見せしますので、**デザインや構成にご納得いただいてから次に進む**形です。

ご契約前ですので、この時点でお客様側の作業や費用は発生しません。

#### ステップ2 — 公開準備（ご契約後）

内容が決まりましたら、ドメインの接続先を切り替える作業を行います。この作業に必要なのは、現行サービスの管理画面での設定変更です。進め方は2通りございますので、ご都合の良い方をお選びください。

**A. 設定内容をお伝えし、お客様側で変更いただく**
弊社から「この項目をこの値に設定してください」という手順書をお渡しします。管理画面のログイン情報を共有いただく必要がないため、セキュリティ面でも安心な方法です。

**B. 管理画面の操作権限をいただき、弊社が設定する**
現行サービスに「サブユーザー招待」の機能があれば、弊社用のアカウントをご招待いただく形が理想です。お客様の作業はほぼなく、設定ミスの心配もありません。

なお、オーナー権限のパスワードそのものを共有する方法は、責任の範囲が曖昧になりますので弊社からはお勧めしておりません。

#### ステップ3 — 切り替え当日

接続先の変更は、インターネット全体に反映されるまで数時間ほどかかります（最大で1日程度）。この間、閲覧される方によって新旧どちらかのサイトが表示される状態になりますが、**サイトが見られなくなる時間は発生しません。**

営業への影響を避けるため、切り替えは営業時間外や定休日に行うことも可能です。

#### ステップ4 — 契約満了前のドメイン移管（将来／任意）

現行のドメイン契約が満了に近づいた時点で、ご希望があればドメインの管理自体を弊社側（Openprovider）へ移すことができます。これにより、サイトとドメインの管理窓口が一本化され、更新手続きや設定変更のご連絡が弊社だけで済むようになります。

この移管には、以下の点にご注意が必要です。

- **満了の1〜2か月前に着手する必要があります。** 直前になると手続きが間に合わず、ドメインが一時的に失効してしまう可能性があります
- **満了直前に自動更新がかかると、その後60日間は移管できないルール**があります。そのため、時期が近づいたら一度ご相談させてください
- 移管には現行サービスから「移管用の認証コード」を取得いただく必要があります

もちろん、**現行のサービスでドメイン管理を続けていただく形でも問題ありません。** その場合も弊社のサイト運用に支障はございませんので、満了時のタイミングでご判断いただければと思います。

### 事前に確認させていただきたいこと

移行を安全に進めるため、下記について教えていただけますと助かります。

1. **ドメイン名** — [ドメイン名]
2. **現在ご利用中のサービス名** — 制作会社様、またはサービス名（Wix、Squarespace等）
3. **そのドメインでメールアドレスをお使いかどうか** — 例：info@[ドメイン名] のような形式のアドレス
4. **現行契約の満了時期** — 分かる範囲で結構です

特に **3番（メール）は重要**です。ドメインはWebサイトとメールの両方で使われており、設定を変更する際にメール側の設定を引き継がないと、**メールが届かなくなる事故**が起こり得ます。弊社では事前に現在の設定をすべて記録し、そのまま引き継ぐ形で作業いたしますので、事前に把握させてください。

### 現在のサイトからの引き継ぎについて

すでに現在のサイトが検索結果に表示されている場合、新サイトへの切り替え時に**ページごとの転送設定**を行うことで、これまでの検索評価を引き継ぐことができます。「お店の名前で検索したときに出てこなくなる」といった事態を防ぐための作業です。こちらも弊社の作業に含めて対応いたします。

### この説明で意図的に省いた技術詳細
- Aレコード / CNAME / ネームサーバー等の用語 → 「接続先設定」に統一
- Cloudflareへのネームサーバー委任案 → 選択肢を増やすと判断が止まるため、必要時に個別提案
- TLD固有ルール（`.fi` は Traficom ポータル経由、`.se` は独自手順）→ ドメイン判明後に確認
- 301リダイレクトの技術的説明 → 「ページごとの転送設定」と表現

- [ ] TLD確認後、移管手順の難易度を再評価
