### 2-2. ご質問への回答

**① 金額が一致しない理由 → 入金が売上の2営業日後になるため**

NETSの入金は、売上日の**2営業日後**に行われる規則的なサイクルになっております。

- 10月12日の売上 → 10月14日に入金
- 10月19日の売上 → 10月21日に入金

したがってPOSの日次売上と同じ日の入金額を並べると必ずずれますが、**2営業日前の売上と比べると一致**いたします。

**② 2日分まとまることはあるか → ございます。今月は2箇所ありました**

CSVの `Number Of Batches`（バッチ数）という列が「2」になっている日が、2日分まとまった入金です。

- **10月20日の入金 €4,730.40** … 10月16日（€1,876.20）＋10月17日（€2,854.20）の2日分
- **10月13日の入金 €3,383.50** … 10月9日＋10月10日の2日分（土日をまたいだため）

おそらく **10月20日の入金**をご覧になったものと存じます。10月18日（日）が休業日のため、週末をまたいで2営業日分がまとめて入金されております。

**③ 手数料について → 今月は取引手数料は引かれておりませんでした**

ご心配されていた手数料ですが、お送りいただいたCSVを確認したところ、

- `Service Fees`（取引手数料）… **全日 0.00**
- `Chargeback / Adjustment`（チャージバック・調整）… **全日 0.00**
- `Subscription Fees`（月額費用）… **10月1日に €10.00 のみ**

となっており、**売上から引かれている取引手数料はございません。** 10月の `Transaction Amount` 合計 €15,937.42 に対し、`Settled`（入金額）は €15,927.42 で、差額は月額費用の €10.00 ちょうどです。

したがって「手数料にしては入金が少なく見える」とお感じになっていた分は、手数料ではなく**上記①の2営業日のずれ**によるものでした。

**なお、手数料の内訳（カードブランド別の料率など）につきましては、お送りいただいたCSVが日次の合計サマリーのため、こちらでは確認ができません。** 取引1件ごとの手数料をご確認されたい場合は、NETSポータルから**取引明細（Transaction report／1件ごとの明細）**をダウンロードしていただく必要がございます。ご契約の料率についてはNETSの契約書、またはNETSサポートへお問い合わせいただくのが確実です。ご希望であれば、取引明細をお送りいただければ改めて1件ごとに突合いたします。

| | 前回の推定 | 実際（CSV確定） |

| 根拠 | 10/18休業による連番の推測 | `Number Of Batches = 2`（CSV列） |

### 3-3. 受領データの限界（返信で「詳細ログが必要」とした根拠）

受領CSVは **Settlement Information（入金サマリー）** のみ。構造は以下の3セクション。

- `Company Information` … 事業者情報
- `Monthly Total` … 月次合計（October: Transaction 15,937.42 / Settled 15,927.42）
- `Settlement Information` … **入金日ごとの合計9行**（取引1件ごとの行は無い）

したがって以下は**原理的に算出不能**であり、取引明細（Transaction report）がなければ回答できない。

- 取引1件ごとの手数料
- カードブランド別・カード種別（デビット/クレジット、EEA内外）の料率差
- どの取引IDがどの入金バッチに入ったかの1対1対応

ただし**日次合計レベルでは完全一致したため、1件ごとの突合を行う実務上の必要性は現時点では無い**（差分2件はPOS側から金額一致で特定済み）。
