**障害区分:** 外部クラウド基盤（Supabase）起因

## 1. お詫び

このたび、2026年10月6日午前、弊社 POS システムにおいて一時的に接続エラーおよび応答遅延が発生し、店舗業務に支障をおかけいたしました。

ご利用の皆様に多大なご不便とご心配をおかけしましたこと、深くお詫び申し上げます。

とりわけ、ログイン・再認証が通らない状態が約12分間続いたことにより、レジ操作の中断や店舗スタッフ様の対応負荷が生じたものと認識しております。業務時間帯での発生であり、影響の重大性を真摯に受け止めております。

重ねて、心よりお詫び申し上げます。

## 3. 発生した症状

お客様側で以下の症状が発生していたと考えられます。

- ログインできない／ログイン画面から進めない
- 操作中に突然サインアウトされる、再認証が求められる
- 店舗情報・組織情報・税設定などの読み込みに失敗する
- 画面が長時間応答しない（最大約90秒でタイムアウト）

### エラー内訳（多い順）

| エンドポイント | 用途 | 件数 |
|---|---|---|
| `/auth/v1/user` | ログインユーザー情報の取得 | 518 |
| `/rest/v1/stores` | 店舗情報の取得 | 44 |
| `/rest/v1/organizations` | 組織情報の取得 | 25 |
| `/auth/v1/token` | 認証トークンの更新 | 25 |

エラーの約77%が認証系（`/auth/v1/*`）に集中しており、**「ログインが通らない」ことが利用者から見た主症状**でした。

## 4. 原因

### 直接原因

クラウド基盤である **Supabase 社側のインフラ障害**です。弊社アプリケーションのプログラム変更、設定変更、データベース変更に起因するものではありません。

### Supabase 社の公式発表

Supabase 社ステータスページにおいて、同時刻帯に以下のインシデントが公表されています。

> **Management API – Degraded Performance**（2026年10月6日 08:13 UTC）
> 「ロールアウトに起因して Management API 依存サービスでエラーが増加し、プロジェクト操作の失敗および FGA 認証エラーが発生している」（複数リージョン）

Supabase 社による更新展開（ロールアウト）作業が引き金となった障害であり、同社にて修正適用済み・経過監視中とされています。

### 技術的な裏付け

弊社側に原因がないと判断した根拠は以下のとおりです。

1. **エラーの種類が基盤層のもの**
   検出されたエラーコードは **522 / 525 / 521**（計 669 件）で、これらはすべて Supabase の接続基盤（Cloudflare ↔ オリジンサーバー間）で発生するエラーです。アプリケーションが返すエラーではありません。
   - `522` = オリジンサーバーへの接続タイムアウト（579件）
   - `525` = SSL ハンドシェイク失敗（64件）
   - `521` = オリジンサーバー接続不能（6件）

2. **アプリケーション層のエラーは1件のみ**
   データベース層のエラー（`PGRST002` = PostgREST がスキーマに接続できない）は 1 件のみで、これも基盤側のデータベース接続断の結果です。

3. **利用者起因のエラーは増えていない**
   4xx 系（認証ミス・不正リクエスト等）は障害時間帯も 169 件で、平常時（毎時約200件）と変わりません。つまり**利用者の操作や弊社の入力検証に異常はなく、サーバー基盤のみが落ちていた**ことを示します。

4. **直前まで完全に正常**
   障害発生前の 25 時間、5xx エラーは **1件も発生していません**。弊社側に段階的な劣化や前兆はなく、外部要因による突発的な事象です。

5. **発生時刻の一致**
   Supabase 社のインシデント公表（08:13 UTC）と弊社システムでのエラー発生（08:41 UTC）が同一の障害ウィンドウ内にあります。

6. **応答時間の推移が基盤障害特有の形**
   平常時 約38ms → 障害時 最大 約90,500ms（90秒／タイムアウト上限に張り付き）→ 復旧後 約38ms。緩やかな劣化ではなく、接続そのものの断絶を示す波形です。

### 補足（正確性のための注記）

Supabase 社の公表文は「Management API」(管理用 API) の障害として記載されていますが、弊社システムで実際に影響を受けたのは**データ参照・認証を行う系統**です。両者は同一のロールアウトに起因する関連事象と判断していますが、弊社の症状そのものについて Supabase 社から個別の確認を得た段階ではありません。この点については同社へ照会を行う予定です。

## 6. データへの影響

**データの消失・破損はございません。**

- 本障害は**接続の断絶**であり、データベースへの書き込み途中でのデータ破損を伴うものではありません
- 失敗したリクエストはサーバーに到達する前にタイムアウトしており、中途半端な状態での記録は発生していません
- 会計・決済処理の不整合を示すエラーは検出されていません

ただし、障害時間帯（08:41〜08:53）に操作を試みられた際、**画面上でエラーとなった操作は保存されていない**可能性があります。該当時間帯に登録・変更作業をされていた場合は、内容のご確認をお願いいたします。

## 8. 再発防止に向けた対応

本障害は外部クラウド基盤に起因するため、弊社で直接防止することはできません。一方で、**発生時の影響を小さくすること**および**検知を早めること**は弊社の責任範囲と考えております。以下に取り組みます。

### 即時対応

1. **Supabase 社への照会**
   本障害の詳細および同社の恒久対策について、正式に説明を求めます。

2. **監視の強化**
   5xx エラーの急増を自動検知し、弊社が即時に把握できる仕組みを整備します。今回は利用者側で異常が顕在化してからの確認となりました。

### 中期対応

3. **認証リトライ処理の改善**
   一時的な接続断で即座にログアウトとならないよう、認証失敗時の自動再試行を強化します。今回エラーの約77%が認証系であり、ここの耐性向上が最も効果的と判断しています。

4. **障害時の利用者向け表示の改善**
   「原因不明のエラー」ではなく、一時的な接続障害であることと復旧見込みを画面上でお伝えできるようにします。

5. **オフライン耐性の検討**
   基盤接続が断たれた状況でも、最低限のレジ業務を継続できる構成について検討を進めます。
