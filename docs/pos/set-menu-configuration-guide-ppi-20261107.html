Prepared 7 November 2026 · Sciometa POS · No changes have been applied to your data

Summary

We reviewed the six set menus in your organisation. Five are configured correctly. One — IZAKAYA SET — has a pricing setup that causes the drink to be charged twice over, and contains one component product that is not needed. This guide explains what is happening, why, and how set menus are designed to be configured. Nothing has been modified; all changes are left to you.

1. How set menu pricing actually works

Understanding this one rule explains all of the findings below. When a customer orders a set menu, the POS does not charge the price shown on the set product. Instead the set is broken into its components, and each component is charged its allocated price plus the price of any option the customer selected:

Charged total  =  Σ ( allocated price  +  option added price )  ×  quantity

Two consequences follow, and both are at the root of the issues found:

  • The component product's own price is ignored. A component priced at €0.00 is perfectly normal and expected — the allocated price is what the customer pays. Setting a component's price does nothing for the set.
  • Option prices are added on top, not substituted. This is the critical point. An option's "added price" means exactly that: it is added to the allocated price. It is not the item's menu price.
The core principle

Put the cheapest variant's price into the component's allocated price, and set each option's added price to the difference (the upgrade cost) from that cheapest variant. The cheapest option should always be €0.00.

Decision required before changing anything

Raising the Drinks allocated price from €0.00 to €4.00 makes the components sum to €12.00 (€4.00 drink + €4.00 × 2 snacks), so the set product's own price must also change to €12.00. The system validates that the set price equals the sum of allocated prices and will reject a mismatch.

You therefore need to decide which price you actually intend to sell at:

  • Option A — sell at €12.00. Set price becomes €12.00. Snacks stay at €4.00 each. This keeps your current per-item values and is the honest sum of what the set contains.
  • Option B — keep €8.00. Set price stays €8.00, drink allocated €4.00, and each snack's allocated price drops to €2.00. This presents the set as a discount on the snacks.

ISSUE 2The "Ice" product should not be a component

IZAKAYA SET currently lists Ice as a third component product. It should be removed. Ice is a preference, not an item — it has no price and no kitchen cost, and both of its choices (Ice / No Ice) are €0.00.

An option group named Ice already exists in your organisation with exactly those two choices. The correct setup is simply to attach that existing option group to the Drinks component, which is the item the preference actually applies to. The customer then picks their drink and their ice preference in one step, as part of choosing the drink.

Keeping Ice as a component also has a side effect worth noting: it prints as a separate zero-priced line on receipts and kitchen tickets, which adds noise for staff without conveying anything the drink line could not carry.

Also worth correcting

The Ice product has no category assigned. Regardless of the set menu, products without a category can behave unpredictably in menu listings and reports. If you keep the product for any other purpose, please assign it a category; if not, it can be retired once removed from the set.

ISSUE 4Two different products both named "Snacks"

Your organisation has two separate products named Snacks, priced €4.00 and €3.00. Both share the same Snack option group, and the €3.00 one is used only by [KIRIN BEER] IZAKAYA STYLE.

If the price difference is deliberate, nothing is broken — the allocated prices are consistent in both sets. However, because the names are identical, staff editing one set cannot tell which product they are looking at, and a future edit could easily be applied to the wrong one. We suggest renaming them to something distinguishable, for example Snacks (Izakaya) and Snacks (Kirin).

ISSUE 5Selection limits left blank

The Drinks group has no minimum selection set, and the Ice group has neither a minimum nor a maximum. Both are single-choice groups, so in practice this is unlikely to cause problems today. Setting them explicitly — minimum 1, maximum 1 — makes the intent unambiguous and protects against the behaviour changing if the group type is ever edited.

4. Set menu setup tips

These rules apply to every set menu you build in future. The five other sets in your organisation already follow them.

Price the cheapest variant in, and charge only upgrades

Decide the cheapest acceptable choice for each component. Its price becomes the component's allocated price, and its option becomes €0.00. Every other option is priced at the difference. A quick test: select the cheapest option for every component — the total must equal the advertised set price exactly.

Ignore the component product's own price

It is not used when charging a set. Components priced at €0.00 are normal. Set the money on the allocated price, every time.

Use option groups for preferences, components for items

If a choice has no price and no separate cost — ice, spice level, sauce on the side, chopsticks — it belongs in an option group attached to the item it modifies. Reserve components for things the kitchen or bar actually produces and that carry revenue.

Keep the set price equal to the sum of its allocated prices

The system checks this on save with a tolerance of one cent. Even within that tolerance, a mismatch means the displayed price and the charged price differ slightly, so aim for an exact match rather than a near one.

Remember that free allowances do not pool across components

Each component's option pricing is calculated independently. A free-choice allowance on one component's option group does not carry over to another component. Configure each component's allowances on their own terms.

Test every set before it goes live

Add the set to a cart and step through each combination, starting with the all-cheapest selection and then one upgrade at a time. Confirm the totals against your intended menu prices. This takes a few minutes and catches exactly the kind of double-charge described in Issue 1.

Before you change anything

Please confirm the intended selling price for IZAKAYA SET first (item 1 in the checklist). All of the price-related edits depend on that single decision, and making them in the wrong order will trip the set-price validation. We are happy to apply the whole set of changes for you once you have decided — just let us know which option you prefer.
