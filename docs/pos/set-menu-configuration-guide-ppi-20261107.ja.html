Prairie Plus International Oy 様 ― IZAKAYA SET の確認結果

2026年11月7日作成 ・ Sciometa POS ・ データの変更は一切行っていません

概要

貴組織に登録されている6件のセットメニューを確認いたしました。5件は正しく設定されています。1件 ―― IZAKAYA SET ―― に、ドリンク代が二重に請求される設定の誤りと、不要なコンポーネント商品が含まれています。本書では、何が起きているのか、その原因、そしてセットメニュー本来の設定方法をご説明します。データの変更は行っておりません。修正はすべてお客様のご判断にお任せします。

1. セットメニューの価格計算の仕組み

この1つのルールを押さえていただければ、以下のすべての指摘内容をご理解いただけます。お客様がセットメニューを注文された際、POSはセット商品に設定された価格では請求しません。セットは各コンポーネントに分解され、コンポーネントごとに按分価格（allocated price）と、選択されたオプションの価格を合算して請求します。

請求額 ＝ Σ（按分価格 ＋ オプション追加価格）× 数量

ここから2つの帰結が導かれます。今回の問題はいずれもこれが原因です。

  • コンポーネント商品自体の価格は使われません。 コンポーネントの価格が €0.00 であることは正常かつ想定どおりの状態です ―― お客様が支払うのは按分価格です。コンポーネントの価格を設定しても、セットの請求額には影響しません。
  • オプション価格は「上乗せ」であり、「置き換え」ではありません。 ここが最も重要な点です。オプションの「追加価格」とは文字どおり按分価格に加算される金額であり、その商品の単品価格ではありません。
設定の基本原則

コンポーネントの按分価格には最も安い選択肢の価格を設定し、各オプションの追加価格にはそこからの差額（アップグレード料金）を設定します。最も安いオプションの追加価格は、常に €0.00 になります。

2. 確認された問題

問題 1ドリンク代が二重請求されています

IZAKAYA SET では Drinks コンポーネントの按分価格が €0.00 に設定されている一方、各ドリンクオプションの追加価格には単品価格がそのまま入力されています。オプション価格はセット価格に加算されるため、お客様はセット価格を支払ったうえで、さらにドリンクの全額を支払うことになります。

ご注文内容セット価格オプション加算実際の請求額本来の金額
IZAKAYA SET ＋ COCA COLA€8.00€4.00€12.00€8.00
IZAKAYA SET ＋ RAMUNE€8.00€5.00€13.00€9.00
IZAKAYA SET ＋ YUZUKA€8.00€7.00€15.00€11.00

同時に、€8.00 というセット価格自体はドリンクにまったく配分されておらず、€8.00 すべてが2品のスナックに乗っています。つまりセット単体で見ると、ドリンクが無料で付いている状態です。ドリンクの売上はオプションの二重請求によってのみ発生しています。

この2つの誤りは互いを打ち消し合っているため、合計金額が一見もっともらしく見えてしまいます。しかし実際には両方とも誤っています。片方だけを修正すると、かえって金額がずれる点にご注意ください。

推奨するオプション価格

最も安いドリンクは COCA COLA と COCA COLA Zero の €4.00 です。この €4.00 を按分価格とし、各オプションの追加価格は €4.00 からの差額に設定します。

修正前にご判断いただきたい点

Drinks の按分価格を €0.00 から €4.00 に変更すると、コンポーネントの合計は €12.00（ドリンク €4.00 ＋ スナック €4.00 × 2）となるため、セット商品自体の価格も €12.00 に変更する必要があります。システムはセット価格と按分価格の合計が一致することを検証しており、不一致の場合は保存が拒否されます。

つきましては、どちらの価格で販売されるおつもりかをご判断ください。

  • 案A ― €12.00 で販売する。 セット価格を €12.00 に変更します。スナックは €4.00 のまま据え置きです。現在の各商品の価格設定を維持でき、セットの内容に見合った合計金額になります。
  • 案B ― €8.00 を維持する。 セット価格は €8.00 のまま、ドリンクの按分価格を €4.00 とし、各スナックの按分価格を €2.00 に引き下げます。スナックを割り引いたセットという位置づけになります。

問題 2「Ice」はコンポーネントにすべきではありません

現在 IZAKAYA SET には3つ目のコンポーネント商品として Ice が登録されていますが、これは削除すべきです。氷は商品ではなく好みの指定であり、価格も調理コストも発生しません。選択肢である Ice / No Ice はいずれも €0.00 です。

貴組織にはすでに、この2つの選択肢を持つ Ice という名称のオプショングループが存在します。正しい設定方法は、その既存のオプショングループを Drinks コンポーネントに付与することです。これにより、お客様はドリンクの選択と氷の有無を一度の操作で指定できるようになります。

なお、Ice をコンポーネントのままにしておくと、レシートやキッチン伝票に €0 の行が独立して印字されます。ドリンクの行に含められる情報であるにもかかわらず、スタッフにとっては確認すべき行が増えることになります。

あわせてご確認ください

Ice 商品にはカテゴリが設定されていません。セットメニューとは別の問題として、カテゴリ未設定の商品はメニュー一覧やレポートで予期しない挙動を示すことがあります。他の用途でこの商品を残される場合はカテゴリをご設定ください。不要であれば、セットから削除したうえで廃止いただけます。

問題 3テスト用・重複のオプションが残っています

Drinks オプショングループに、過去の設定作業で作られたと思われる無効状態の選択肢が3件残っています。現在は無効のためお客様への影響はありませんが、グループの管理が煩雑になり、誤って有効化されるおそれがあります。

test€1.00無効削除 ― テストデータ

問題 4「Snacks」という同名の商品が2つ存在します

貴組織には Snacks という同じ名称の商品が2つ登録されており、価格はそれぞれ €4.00 と €3.00 です。両方とも同じ Snack option グループを共有しており、€3.00 の方は [KIRIN BEER] IZAKAYA STYLE でのみ使用されています。

この価格差が意図的なものであれば、不具合ではありません ―― 按分価格はどちらのセットでも整合が取れています。ただし名称が同一であるため、セットを編集する際にどちらの商品を操作しているのか判別できず、将来の編集作業で誤った方に変更を加えてしまうおそれがあります。Snacks (Izakaya)、Snacks (Kirin) のように区別できる名称へのご変更をお勧めします。

問題 5選択数の上限・下限が未設定です

Drinks グループには最小選択数が設定されておらず、Ice グループには最小・最大のいずれも設定されていません。どちらも単一選択（single）のグループであるため、現時点で問題が生じる可能性は低い状態です。ただし、最小1・最大1と明示的に設定しておくことで設定意図が明確になり、将来グループの種別が変更された場合にも挙動が変わらないよう保護できます。

4. セットメニュー設定のコツ

以下は、今後セットメニューを作成される際に共通して当てはまる原則です。貴組織の他の5件のセットは、すでにこれらに沿って設定されています。

最安の選択肢を価格に含め、差額のみを課金する

コンポーネントごとに「最も安い選択肢」を決めます。その価格をコンポーネントの按分価格とし、対応するオプションの追加価格は €0.00 にします。それ以外のオプションには差額を設定します。確認方法は簡単です ―― すべてのコンポーネントで最安の選択肢を選んだとき、合計がセットの表示価格とぴったり一致すれば正しく設定できています。

コンポーネント商品自体の価格は気にしない

セットの請求時には使用されません。コンポーネントの価格が €0.00 であることは正常です。金額は必ず按分価格の側に設定してください。

「好み」はオプショングループ、「商品」はコンポーネント

氷の有無、辛さの調整、ソースの別添え、箸の要否など、価格もコストも発生しない選択は、対象の商品に付与するオプショングループで表現します。コンポーネントは、キッチンやバーが実際に提供し、売上が発生するものに限定してください。

セット価格と按分価格の合計を一致させる

システムは保存時に1セントの許容差でこれを検証します。許容範囲内であっても、不一致があれば表示価格と請求価格がわずかにずれます。「ほぼ一致」ではなく「完全一致」を目指してください。

無料選択枠はコンポーネント間で共有されない

オプションの価格計算はコンポーネントごとに独立して行われます。あるコンポーネントのオプショングループに設定した無料選択枠が、別のコンポーネントに引き継がれることはありません。無料枠は各コンポーネントで個別にご設定ください。

公開前に必ず動作確認を行う

セットをカートに追加し、組み合わせを一つずつ確認します。まず全コンポーネントで最安の選択肢を選び、その後1つずつアップグレードしてください。各段階の合計金額が意図した価格と一致するかをご確認ください。数分で完了する作業ですが、問題1のような二重請求はこの手順で確実に発見できます。

修正に着手される前に

まず IZAKAYA SET の販売価格（チェックリストの項目1）をご決定ください。価格に関する修正はすべてこの1つの判断に依存しており、順序を誤るとセット価格の検証エラーが発生します。ご決定いただければ、一連の修正を弊社で適用することも可能です。どちらの案をご希望か、お知らせください。
